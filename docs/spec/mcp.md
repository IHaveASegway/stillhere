# MCP server

Status: v1 · 2026-10-14 · the tool contract of `stillhere mcp` (#15, [ADR 0006](../adr/0006-ai-mcp-and-narrated-highlights.md)) · server in `internal/mcp`, use cases in `internal/app/mcp.go`, the agent's guide in [plugins/stillhere/skills/stillhere/SKILL.md](../../plugins/stillhere/skills/stillhere/SKILL.md)

`stillhere mcp` is the interface an agent calls for deep detail on a platform (a group of repositories) or one repository: what landed, what lasted, who knows the code, each answer with its provenance and the caveats that could make it wrong. It answers from the same use cases and report types as the command line, so its numbers are the report's numbers. No tool computes a metric.

## The server

```
stillhere [--db FILE] [--mailmap FILE] [--log-level L] mcp [--run ID] [--me EMAIL] [--allow-emails] [--allow-source]
```

| Flag | Effect |
| --- | --- |
| `--run ID` | Every answer reads that run. Without it, each call reads the latest complete or partial scan, so a scan published during a session is seen at the next call, and the first answer that reads it carries a `run-changed` caveat. A run facts.db does not hold (never published, or deleted by retention) is an error on every call that names the latest scan and says how the user restarts the server. |
| `--me EMAIL` | The user's canonical email, after `.mailmap`. Only `person` about that email (an empty `name`) shows the person's own AI-assisted share, through `app.Me`; nobody else's answer ever does ([ADR 0007](../adr/0007-ai-assisted-attribution.md)). `changes` tags AI-assisted commits on the user's own entries only. When no one in the run has the email (another address of the user's, which the mailmap folded), `person` with an empty name says so, and every `person` answer carries a `me-not-in-run` caveat. |
| `--allow-emails` | Answers carry emails. Without it every email is replaced by a stable id. |
| `--allow-source` | Answers carry commit subjects, and `diff` serves diffs, which needs git: `--mailmap` applies. Without it `diff` refuses and says how to allow it. |

- **Transport.** Local stdio on the official SDK (`github.com/modelcontextprotocol/go-sdk` v1.8.0), newline-delimited JSON-RPC. Only protocol messages go to stdout; the log goes to stderr. The server ends when the client closes stdin, or on a signal. A line from the client that is not a JSON-RPC message is answered with JSON-RPC's own error for it, a parse error (`-32700`) or an invalid request (`-32600`) with a `null` id, logged at warn and skipped: the session goes on, as JSON-RPC 2.0 asks, where the SDK's reader alone would end it.
- **The store cannot write.** facts.db is opened with `sqlite.OpenReadOnly` (SQLite's `mode=ro`): nothing is created, migrated or cleaned up, and every write fails inside SQLite. It is opened on the first call that needs it and again after a failure, so a server started before the first scan answers each call with what to run (`stillhere scan PATH...`) until there is one. `metrics` reads no store.
- **One call at a time.** Calls are served in turn, and a published run's facts are read once and kept (a run never changes once published), so an agent's tenth question about a run does not read facts.db again. A call waits for the one before it unless its client cancels it first, and each git command of `diff` has 30 seconds, so no call holds the others for long.
- **Git, for diffs only.** With `--allow-source` the server holds a git runner on the analysis profile: offline, hardened, external diff and textconv off ([git-invocation.md](git-invocation.md)). Without it the server holds none.

Claude Code:

```sh
claude mcp add --scope user stillhere -- stillhere mcp --me you@example.com
```

## Every answer

An answer is one text content holding one compact JSON object, in the rules of [report-json.md](report-json.md#rules-that-carry-forward-whatever-the-format): fields in a fixed order, empty lists `[]`, an absent section `null`, invalid UTF-8 as U+FFFD, a number that is not finite as `null`. The object opens with `provenance` and closes with `page` (paged answers only), `caveats` and `withheld`.

| Field | What it holds |
| --- | --- |
| `provenance` | `run_id`, `as_of`, `policy` (sha256), `heads[]` of `{repo, key, branch, sha}`, `metrics[]` (the metric@version of every number in the answer), `heads_total` and `heads_sha256`. `heads` lists every repository the answer covers when it covers 10 or fewer, and in a detailed answer while it fits the budget; otherwise the repositories the answer names (its page, the repositories of its values, changes and picks). `heads_total` counts every repository the answer covers, and `heads_sha256` is the SHA-256 of all their heads as `repo key branch sha` lines, so two answers can be checked against one HEAD set. `forge` dates the GitHub data the run read for those repositories, as in [report-json.md](report-json.md); when `heads` is cut, `forge.repos` is cut with it to the repositories still listed, `forge_repos_total` counts them all (it is absent when nothing was cut), and `forge.as_of` stays the oldest sync over all of them. `metrics` answers with `{source: "registry", version, metrics}` instead: definitions are code. |
| `page` | `{offset, limit, total, next_cursor}`: pass `next_cursor` as `cursor` for the next page; `null` on the last. A cursor names its run, and one from another run is refused. |
| `caveats` | `[{code, message, repos}]`: the report's codes ([report-json.md](report-json.md#caveats)) and the ones below. |
| `withheld` | What this server keeps from the agent: `emails`, `source`. |

**No list grows with the platform.** An answer's main list is paged; every other list in it (a table's rows, a person's repositories, values and ranks, a change's people, the top tiers, the run's warnings) holds its first rows with its count in a `*_total` field beside it. Ordered lists keep their order; lists of values and ranks keep the largest: the scopes whose denominators, then numerators, are largest, and the rank tables with the most eligible people.

**Names, not ids.** People are named by their display name as the reports print it. The field that would hold a person's canonical email (`email`, a person subject's `key`) holds it with `--allow-emails`, and otherwise the person's id: `p-` and the first 10 hex digits of the SHA-256 of the canonical email. The id is stable across answers, sessions and runs, so an agent can join two answers on it and pass it back to `person`. It is a pseudonym, not an anonymisation: anyone who already holds an email can compute its id. A reviewer the forge could not link to an email is `@login` (`identity.LoginKey`); an address with an empty local part (`@example.com`) is no login, and gets an id like any other. A person the reports show without a name, because git recorded none or because it gives an address away ([report-json.md](report-json.md#rules-that-carry-forward-whatever-the-format), "Where emails go"), has `name` `""`, and the server's own sentences, and the fields that say whom an answer is about, name them by id.

**Emails are withheld at the egress.** Without `--allow-emails`, every string of every answer and every error message, object names included, passes a filter after the answer is encoded, so a field added later, a warning that quotes an author or an error that names a person cannot carry an email out. The filter has three layers, from the most certain to the least, as data-loss-prevention tools pair transformations by field with detectors over free text (Google Cloud's Sensitive Data Protection; Microsoft's Presidio). Finding an address is one rule, `internal/redact`'s (`redact.Addresses`, `redact.Place`), which the command line's pages apply too ([report-json.md](report-json.md), "Where emails go"); only what replaces an address differs, an id here and a fixed label there:

1. **Where an email is.** A person's canonical email sits only in a member named `email`, or in the `key` of an object whose `kind` is `person` ([report-json.md](report-json.md), and #26's identities). Such a value becomes the id whatever it looks like: a dotless domain (`root@localhost`), an IP literal (`ip@[10.0.0.1]`), a Unicode or quoted local part, an empty one (`@example.com`). Only a login (`@name`, `@name[bot]`) and an id stay as they are.
2. **The run's vocabulary.** Every email of the run's people (`app.Names`) is replaced, as a whole address, wherever it appears: in a caveat or a warning, a commit subject, a patch or a path. An address with an empty local part is replaced only where no local-part character comes before its `@`, so it is never the end of another address.
3. **How an email looks.** In text that is not a path (`path`, `old_path`), what still looks like an address is replaced too: a local part of letters and digits in any script and RFC 5322's atext, and a domain of dotted labels that ends in letters (a top-level domain), or an IP literal. So a version pin (`lodash@4.17.21`, `actions/setup-go@v5.0.1`) or a metric id (`durable@1`) stays as it is, and so does the `user@host:path` of an scp-like remote (`git@github.com:o/r.git`, a repository key): a colon then a path, not a colon then a space or the end. A dotless address the run does not know is left to the first two layers, since `pkg@latest` is far more common in source than a person's address on a host name.

The log at info level never carries an email either way.

**The AI-assisted share of few people stays local.** A share over the landings of one or two people is close to one person's own share, which [ADR 0007](../adr/0007-ai-assisted-attribution.md) shows only to that person, and shares add up over the scopes (a group's landings are its repositories', the whole run's every repository's), so a share withheld on its own could be worked out from those shown around it: a group's less its shown repositories'. One decision per run (`app.AIShares`, [ADR 0007's amendment](../adr/0007-ai-assisted-attribution.md#amendment-the-shares-that-leave-the-machine)) says which shares leave, and every answer reads it, so no two answers disagree and none can be subtracted from another:

- A scope's share (the whole run's, a group's or a repository's) is withheld when fewer than three humans are credited with a commit landed in its window (365 days).
- Bottom-up over the run, its groups and their repositories, when the withheld children of a scope leave a part of it that covers one or two people, more children are withheld, the smallest first, until the part covers three or more; when no child can, the scope's own share is withheld. A shown share less the shown shares below it then covers no one or at least three people, at every level and across levels.
- The whole run's share is decided on only where an answer shows it: in the overview of every repository, which a run scanned with `--scope all`, or without groups, has.

`overview` sets a withheld share to `null`, its `num` and `den` with it, and says so (`ai-few-people`); `explain` refuses it, and no answer's `values` hold it. Neither the caveat nor the refusal points at another share. The local report keeps showing every share: the egress is stricter than the terminal, as it is for emails.

**Repository text is untrusted.** Names, paths, commit subjects, warnings and patches come from the repositories and can carry prompt injection. Every tool description, the server's instructions and the skill say so, and the server's own sentences quote every name they hold (`"Lena Lead" (id p-…)`), so injected text reads as data rather than as the server's prose; the server does not try to recognise an injection.

**Size.** An answer stays under 40,000 characters (about 10,000 tokens at 4 characters a token): under Claude Code's warning at 10,000 tokens, under the 50,000 characters past which Claude Code saves a result to a file, and well under its 25,000-token cap (`MAX_MCP_OUTPUT_TOKENS`). An answer over it is rendered again, cut a step at a time, the least useful part first: the HEADs of repositories it does not name, then a diff's patch, then half the page, then half the rows of each list. It fails only when one item is still too large, and the error names the arguments of that tool that narrow it.

**`response_format`.** `concise` (the default) carries the numbers needed to answer: lists of repositories as one-line summaries, short SHAs (12 hex digits, which every tool that takes a change accepts), each list cut to 10 rows (5 for who-knows) with its `*_total`. `detailed` carries every field, for follow-up work: whole repository parts, per-section provenance and caveats, full SHAs, 50 rows (25 for who-knows).

**Errors** are tool results with `isError`, so the model sees them, and each says what to pass or run instead: the run's scopes for an unknown scope, the candidates with their ids for an ambiguous name, a suggestion for a misspelt one, `stillhere scan` for an empty database, how the user restarts the server for a flag set wrong.

## Resolving names

| Argument | Accepts |
| --- | --- |
| a person (`person.name`, `changes.person`, `explain.subject`) | a display name as the reports print it, without case; the start of each word when that matches one person only (`lena`), with a `name-match` caveat; an id `p-…`; an email; a login `@name`. Two matches are an error listing both, with their ids, surviving lines and repositories. A name the reports withhold, because it gives an address away, matches no one and is suggested for no misspelling, and every miss says so, so a miss confirms nothing: such a person is passed by id or email. An empty name is `--me`'s person. |
| a scope (`overview.scope`, `changes.scope`, `highlights.scope`, `identity_candidates.scope`) | empty for the whole run; a group name; a repository name or key (a remote pasted with its credentials finds its scrubbed key); `group:NAME`, `repo:NAME` or `GROUP/NAME` to say which. |
| a repository (`who_knows.repo`, `diff.repo`, `explain.subject` for `repo` and `area`) | a repository name or key, `repo:NAME` or `GROUP/NAME`. |
| a path (`who_knows.path`) | repo-relative, any prefix down to one file; or absolute inside a clone the run read, which names the repository too. A path is the repository's, as answers give it (`src/pins/lodash@4.17.21/index.py`): pass it back as it is. |

## Tools

All tools are read-only, idempotent and closed-world (`readOnlyHint`, `idempotentHint`, `openWorldHint: false`). Every tool that pages takes `response_format`, `limit` (1 to 100) and `cursor`.

| Tool | Arguments | Answers | From |
| --- | --- | --- | --- |
| `overview` | `scope`, `rank` | A platform, a repository or the whole run: `run`, `overviews[]` (scope, totals, `people` and `week` tables, concentration, knowledge loss, AI-assisted and bot shares), `repos[]` (paged; concise: one row each with size, people, top authors, concentration, shares, landings and caveat codes; detailed, and always for one repository: the report's whole repository part, card, still-here and week tables), `ranks[]` only when `rank` names a ranked metric, and the run's `warnings` with `warnings_total`. The whole run's answer is an index: one paged list of its groups, then its repositories, the groups in `overviews` (concise: their tables `null`, which `overview(scope=GROUP)` has) and the repositories in `repos`, with the rank tables of the page's groups; an overview of every repository (a run scanned with `--scope all`, or without groups) is on every page. | `app.Overview` over `app.Report` |
| `person` | `name` | `person` (`name`, `key`, `bot`, `repos` with `repos_total`), `own_page`, `values[]` with `values_total` (concise: the whole-run values, where they differ from the one group's, and per metric the largest group values; detailed adds the largest repository values), `ranks[]` with `ranks_total` (the person's place in each ranked metric's table, the largest tables per metric, with `eligible`, `rank_lo`–`rank_hi` of `of`, the 95% interval of the estimate and `n`). `own_page` is true only for `--me`'s person, and only then do `values` hold `ai_assisted@1`. | `app.Me` for `--me`, else `app.Person` |
| `who_knows` | `path`, `repo` | `path`, `repo`, and per repository with code under the path (paged): its lines, prod files, files with a majority owner, `majority_owners`, `top_authors` (up to five), `recent_landers` (90 days), `recent_reviewers` (90 days, from the GitHub data the run kept; `[]` too where it has none, which `provenance.forge` then does not list), `bots`, each list but `top_authors` cut with its total. A routing answer, not a rank. | `app.WhoKnows` |
| `changes` | `scope`, `since`, `person` | `window` [since, as-of), `person` (the one asked about: their name, or their id when the reports show none) and `changes[]`, newest first (paged): repository, landing, time, merge, `people[]` credited with its non-merge commits (with `people_total`), each with durable@1's cluster (concise `durable: {kept, added}`, for changes 90 to 365 days old) and simplifying@1's (`removed`, the last 90 days), `merged_by` (concise: the merger's name, absent when the reports show none; detailed: the merger as a subject, with their id), `reverts`, `reverted_by`; `title` only with `--allow-source`; `ai_assisted` only on `--me`'s entries. `since` is `YYYY-MM-DD`, RFC 3339 or `Nd`; the default is the policy's week, and the history covers 365 days. | `app.Changes` |
| `explain` | `metric`, `subject`, `subject_kind` (`person`, `repo`, `group`, `area`), `path` | `metric` (concise: id, question, unit, ranked, ratio, eligibility; detailed: the whole definition), `subject`, `values[]` with `values_total` (the whole-run value and the largest group and repository values), and for a ranked metric about a person `changes[]` (paged): each counted landing with its `num` and `den`, the clusters the bootstrap resamples. `title` only with `--allow-source`. `ai_assisted` about a person is refused for everyone, and about a repository or group whose share the run's decision withholds. An area is a top-level directory (`subject` the repository, `path` the directory). | `app.Explain` |
| `highlights` | `period` (`week`, `month`, `quarter`), `scope` | `top_tier[]` with `top_tier_total`: per ranked metric and rank scope, `of` (the eligible people), `people_total` (those whose 95% rank interval reaches first place) and `people`, them by name, not ordered among themselves, unless they are more than a third of `of`: then no one stands out, `people` is empty and a `no-standout` caveat says so; `lasted[]`: durable@1's cohort clusters that kept the most lines (the cohort window, whatever the period); `removed[]`: the period's simplifying@1 clusters that removed the most prod lines and were not reverted. Five changes each. Rule-based picks, never a score of a person. | `app.Highlights` |
| `identity_candidates` | `scope` | `report.Identities` as #26 builds it, whole but for its provenance, which is cut as every answer's is: candidates, their evidence and suggested `.mailmap` lines, never applied. Without `--allow-emails` the emails in it are ids. | `app.Identities` |
| `metrics` | `metric` | The registry: concise `{id, question, ranked, ratio}` (`ratio` only when true); detailed, or `metric` for one, every field of the definition. | `app.Metrics` |
| `diff` | `change`, `repo`, `path`, `max_chars` (1,000 to 24,000) | Only with `--allow-source`. One landing against its first parent (a root commit as all added): `files[]` with numstat, the run's class of each path (a role, or why it adds nothing) and `in_patch`, with `files_total`; `patch`, the unified diff of the files with a role, cut at `max_chars` bytes on a line, and cut further, on a line, when its JSON escapes would put the answer over the budget; `truncated`. `change` is a landing SHA or its first 7 or more hex digits. | `app.Diff`, git `diff-tree` |

### Caveat codes the MCP answers add

| Code | When |
| --- | --- |
| `name-match` | A person was matched by the start of each word of the name given. |
| `run-changed` | Without `--run`: this answer reads another run than the previous answer, because a scan was published in between. |
| `history-window` | `changes` was asked about time before the run's 365-day history. |
| `durable-window`, `simplifying-window` | `changes`: a change younger than 90 days has no durable@1 cluster yet (which is not a 0), and one older than 90 days no simplifying@1 cluster. |
| `highlights` | Always on `highlights`: picks for recognition, not a ranking of people. |
| `no-standout` | `highlights`: in these tables more than a third of the eligible people could be first, so their top tiers are counted, not listed. |
| `ai-few-people` | `overview`, or any answer that leaves a share out: the AI-assisted share of these scopes is withheld, because fewer than three people landed in its window or it would let a withheld share be worked out from those shown. |
| `me-not-in-run` | `person`: no one in the run has `--me`'s email, so no answer is the user's own page. |
| `truncated` | `diff`: the patch was cut at `max_chars`, or further so the answer fits, or more than 1,000 files with a role were left out. |

## The test

`TestMCPTools` (codebase.md's only test for this package) drives the real server through the SDK's own client over its in-memory transport, on a facts.db made by `app.Scan` with the adapters `internal/cli` builds. Its first run holds both fixtures as one platform. It asserts the oracle numbers the answers show ([SPEC.md](../../testdata/fixture/SPEC.md): the still-here rows, knowledge loss 4/34, the concentration walk, the sibling's surviving@1 credit and bot share, Lena's durable@1 rank 1–1 at 26/30 with n 10, who-knows by a relative and an absolute path, S1 and S2's removals, the cohort's longest-lived change), paging and cursors, the budget cutting a page and its cursor leading on, a name matched by its first word, an ambiguous one listing both candidates, quoted, with their ids and a misspelt one suggesting the right one, no commit subject and a refused `diff` without `--allow-source`, `diff` and emails with both, the AI-assisted share on the `--me` person's page only, that page equal to a lead's view of the person but for that share, `--run` and `--me` set wrong, a panicking call answered as an error, a stray line on stdin answered with `-32700` while the session goes on, and every answer under the 25,000-token cap at 4 characters a token. A second scan then adds a repository whose people have emails of every odd shape (a dotless domain, an IP literal, a Unicode and an apostrophe local part, one in a commit subject followed by a colon), a version pin in a path and a patch whose JSON escapes double it, and one repository of a single person: the next answer carries `run-changed` and a cursor of the first run is refused; no email of either run appears in any answer or error without `--allow-emails`, `identity_candidates` included, and each id is the one `person` resolves; two of those people's names are their addresses' local parts (`dev`, `Root`), so `made_of` withholds exactly those two (`name` `""`, `name_withheld` true), `person` reaches them by id, and `person(name: "Root")` is refused without pointing at Root; the version pin stays in the path, the subject and the patch; the patch is cut to fit; and the one-person repository's AI-assisted share is withheld. A case checks the filter's three layers on crafted text. A last one scans shares that add up, into facts.db files of their own, and compares each answer with the shares the local report shows: a group of a four-person repository and a one-person one, where the group's share less the repositories' shown cannot give the one person's, neither repository's share is shown in an answer about the group or about it alone, and `explain` refuses both without pointing at another share; a group of three one-person repositories, whose share is shown and theirs are not; and, scanned with `--scope all` beside a one-person repository named on its own, a run whose share less the shares shown cannot give that person's either.

## Choices and their reasons

- **Nine tools around questions, not tables** ([ADR 0006](../adr/0006-ai-mcp-and-narrated-highlights.md); Anthropic, "Writing effective tools for agents", 2025). A tool per table would make an agent stitch rows and ids together over many calls.
- **JSON, compact.** The report types are JSON already, which keeps one published shape; Anthropic's guidance finds no format best for every agent, and JSON lets an agent quote numbers exactly. Indentation would cost tokens and tell the model nothing.
- **Text content only**, no `structuredContent` with an output schema: the model reads the text, and a second copy of every answer would double its tokens.
- **The latest run per call**, not pinned at start: a long session sees the next scan, and `run-changed` says when two answers read different runs. `--run` pins a session.
- **No schema defaults.** SDK v1.8.0 applies a schema's `default` to `arguments: null` by writing into a nil map, which panics and ends the process; the defaults are in the handlers and the descriptions instead.
- **Emails by structure first, by shape last.** A pattern alone either misses addresses (a dotless domain, an IP literal, a Unicode local part) or rewrites what is not one (a version pin in a path, which the agent then cannot pass back). Where a person's email sits is part of the published shape, and the run knows every address it holds, so those two layers are exact; the pattern is left only for addresses no one in the run has, and kept off paths.
- **Bounded lists, with their totals.** A provenance that listed every HEAD, or an index with every group, made the entry tools fail on an organisation of a few hundred repositories; cutting a list keeps the answer and its count says what was left out. The HEAD digest keeps a cut provenance checkable.
- **A tolerant reader on stdin** (Postel's robustness principle, RFC 1122 §1.2.2): one stray line costs one error reply, not the session.
- **AI-assisted shares by one decision per run, with secondary suppression** ([ADR 0007's amendment](../adr/0007-ai-assisted-attribution.md#amendment-the-shares-that-leave-the-machine); Hundepool et al., *Statistical Disclosure Control*, Wiley 2012, ch. 4). A threshold checked one scope at a time leaks by subtraction, and a decision made per answer lets two answers disagree; withholding the parent of every small scope would cost most groups' shares. Withholding the smallest scope that closes the gap keeps the most shares that cannot give a small one away.
