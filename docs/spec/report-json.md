# Report JSON

Status: v1 shape as emitted by `report.Build` and `report.JSON` (#11), revised 2026-10-15 (#108, #107, #105, #109) · `stillhere.report/v1`. No external consumer exists yet, so the shape may still change until the first tag; after it, the rules below hold.

`stillhere week`, `scan` and `report` print one `stillhere.report/v1` document with `--format json`. The read commands (`explain`, `who-knows`, `me`, `identities`, `validate`, `label --plan`, `metrics`) print their own answers, described [below](#the-read-commands-answers). The Go types in `internal/report` are the same shapes, so the MCP server (#15) answers from them too.

## Rules that carry forward, whatever the format

- **Schema changes.** Adding a field does not change the version. Renaming a field, removing one, or changing what it means does. Reports can always be regenerated, so the old and new shapes are never written side by side.
- **Null and empty values.** An absent section is `null`; an empty list is `[]` and an empty map `{}`, never `null` and never omitted.
  - `null`: `run` in a week report (and in a scan that stored nothing); `still_here` for a repository without line facts (every week run, shallow and partial clones) and, with `week`, for a failed repository; `card.age` when the first commit is unknown; a share, a concentration or a `review_coverage` whose metric gave no value (`review_coverage` without GitHub data); the numbers `surviving@1` gives (`size.prod_files`, `size.prod_lines`, `card.people`, `totals.prod_files`, `totals.prod_lines`, `totals.people`) and `card.bots` when the repository or scope has no line facts; a week row's or total's `lines_added` and `prod_lines_added` when no landing's lines are known (a partial clone, #74); `week` (a repository's or an overview's) and `totals.landers` when no repository of the scope has history that covers the landed window (a shallow clone whose boundary is inside it, #74), where a covered window in which nothing landed has a `week` whose `total` is 0 and no rows; `landings.last` when the history holds no landing; so that "unknown" never reads as 0.
  - `[]`: `errors.blame` in a clean scan, `warnings` with none, `ranks` without `--rank`.
  - Each kind of error has exactly one list, never a second list under another name.
- **Strings and numbers.** Strings are UTF-8. git does not guarantee it: a commit written without an encoding header (by cvs2git, early git-svn or JGit) keeps its Latin-1 bytes, and `--encoding=UTF-8` leaves them as they are. Such bytes become U+FFFD in every format, as encoding/json v1 wrote them, so one odd commit cannot fail a report. A number that is not finite (NaN, an infinity) is `null`. The document is written only once it is whole, never cut off halfway.
- **Where emails go.** Emails appear in JSON, the machine output, only as the join key of a person row (`email`, and a person subject's `key`), and never in text or Markdown, which people read, paste and share. No other field prints a part of one either.
  - **A display name that gives an address away is withheld in every format**, JSON included: one that holds an `@`, as an address typed as a name does, or that is, ignoring case, a local part of any person's address in the run (the whole of it, the part before a `+tag`, or a GitHub noreply address's login), as GitHub names a commit by the login of an account without a profile name. `John Doe` on `john.doe@` is a name and stays. The rule is the name's, decided over every address of the run (`identity.Directory.Withheld`), not the row's own address alone: when `jdoe@corp.example` is named `jdoe`, the name is withheld on `john.doe@mail.example` too if he is also called `jdoe`, or the page would print on one row the local part it withholds on the other, and the caveats and the MCP server's name lookup would point from one to the other. The identities answer applies the same rule ([identities.md](identities.md#output)).
  - Such a row has `name` `""` and `name_withheld` `true`, so a reader that drops the email fields, as the MCP server does without `--allow-emails`, sends no address under another field's name. A person git records without a name has `name` `""` and `name_withheld` `false`.
  - **Bots.** A bot's or an agent's address is no person's, so its local part withholds no name: `dependabot[bot]` and `Copilot` are shown, though each is its own noreply login. A bot's name that holds an `@` is withheld like anyone's, so no text or Markdown page prints it.
  - **GitHub logins.** An account that no commit of the run links to an email is keyed `@login`, the login lowercased, as GitHub compares logins, and named by the login as GitHub last showed it (`@Zoe` for the key `@zoe`; `identity.Directory.Reviewer` and `Name`; a run stored before #69, which kept the case in its keys, is read with them lowercased), an app `@login[bot]` ([ADR 0004](../adr/0004-github-behind-sync-boundary.md)), even when the login is also the local part of an address in the run. A login is the account's public name, which GitHub shows beside every review the row counts, and the page ties it to no address: the forge could not link the two, which is why the row is keyed by login. Withholding it would hide it from text and Markdown only, since `email` and `key` hold it in JSON and over MCP, and a `name_withheld` on a login would tell an agent that the login is a local part in the run, which the login alone does not. Revisit if a rule ever links logins to addresses by their local parts.
  - **Addresses in repository text** are withheld in every format, JSON included, and printed as `(address withheld)`: a commit subject that thanks a teammate or quotes a customer, a git message, a directory's name. The rule is the one the MCP server's egress applies, `internal/redact`'s: an address of a person of the run wherever it appears, as a whole address, and in text that is not a path (`path`, `old_path`) whatever looks like an address (a domain that ends in letters, or an IP literal; not a version pin such as `lodash@4.17.21`, a metric id such as `durable@1`, or the `user@host:path` of an scp-like remote). A path keeps an address no one in the run has, so it stays the repository's path. The renderers apply it to every string of the document's published shape but the fields above (`report.Text`, `report.Markdown`, `report.JSON`), so a field added later is covered too; the model itself keeps the text, which the MCP server withholds by its own operator, an id. The label is fixed, and says nothing about the address, not even which of two it was. The people are the run's, not the page's: every document carries the run's addresses (every address the run shows someone by, `identity.Directory.Addresses`, in a field no format encodes), and the renderers withhold by them and by the page's own, so an address in a dotless domain (`root@buildbox`) of a person of the run who is not on the page is withheld too, as the MCP server's egress withholds over the run's people (#90).
  - **Labels.** Text and Markdown show a person without a name as `(no name 1)` and one whose name is withheld as `(name withheld 1)`, numbered in the order the page first names them: the same person keeps one label everywhere on a page, two such people stay apart, and a label matches nothing outside its page. git records any name, so a name with a label's shape, or one that starts with a double quote, is printed quoted, as Go quotes a string (`"(no name 1)"`): no name reads as a label, and no two names print alike unless they are alike. A label is a counter, not a hash: the `(no name 1a2b3c)` of earlier versions, the start of the email's SHA-256, let anyone who guessed an address confirm it with one hash (ENISA, *Pseudonymisation techniques and best practices*, 2019, §7.2).
  - AI payloads never contain emails, absolute paths, warnings or errors; that is specified with the narrator in M4.
- **Overviews replace group rollups.**
  - `overviews` has one element per group, in `groups` order, with `scope: {"kind": "group", "key": <name>}`. A run with `--scope all`, or without groups (only repositories named directly), has one more, first: every repository, `scope: {"kind": "all", "key": ""}`.
  - Each overview starts with `repos`, one row per member repository, its card's numbers on one line (#105): landings in the landed window and the history, people, prod lines, knowledge loss, concentration (`authors_in_prefix`), review coverage and the last landing.
  - Its person rows are the metrics' values for the overview's scope: counts for one email summed within the group, and `files_with_majority` summed per repository with the concentration walk re-run on the summed column ([blame-collector.md](blame-collector.md#reductions-the-fixture-asserts)). No metric walks every repository at once, so the every-repository overview's `concentration` is `null`.
  - A person in two groups is a row in each. Groups are kept apart as ranks are ([metrics.md](../metrics.md#ranking-rules)): there is no cross-group total unless `--scope all` asks for one, so in a run with groups a repository named directly has a card and is in no overview.
- **Joining.** People are joined on the canonical email after mailmap, never on a private person id. Repositories are joined on `key` (`groups[].repos`, `provenance.heads[].key`, `scope.key`).
- **Hotspot units.** `window_main_dev_ownership` is a 0–1 ratio and coupling `degree` is an integer percent ([hotspots-code-maat.md](hotspots-code-maat.md)). These fields exist only if hotspots ship.
- **Warning codes.** Warnings are `{code, message}`. A repository's warnings are on the repository (`repos[].warnings`) and its card's caveats: `duplicate-repo` (on the repository kept: another clone of its remote was skipped), `shallow-clone`, `shallow-window`, `partial-clone`, `ignore-revs` (its own `.git-blame-ignore-revs` was not used, or not whole), `head-after-now` (#70: the run read the newest commit on its branch's first-parent chain committed before `--now`, an older commit than the branch's head; the message names the commit read, when it was committed, the head, and how many landings came at or after `--now`), `dated-after-now` (#70's review, scan only, when blame ran: landings below the commit read are dated at or after `--now`, as a backdated commit or a clock that ran ahead leaves; the message names the commit read and counts them), `inline-tests` (scan only, when blame ran: prod `.rs` files at HEAD hold `#[cfg(test)]` items, Rust's unit tests inside the source; the message counts the files and their non-blank lines and gives their share of the surviving prod lines, [classification.md](classification.md#rust-inline-tests)), `other-refs-unread` (wave 10's review, scan only: git could not walk the commits of the clone's other branches and tags, as a branch naming a parent the clone lacks leaves, so `knowledge_loss@1` counts no commit off the default branch there, while every other fact stands; the message gives git's exit, not the ref; a ref to an object the clone lacks is skipped without one, [week-collector.md](week-collector.md#commits-on-other-refs-scan)). The run's are in the top-level `warnings`: `excluded-repo` (one per repository `--exclude-repo` left out, which is how the report lists them), `path-failed` (one per path that gave no repository: a PATH that is neither a repository nor a group, a directory with no repository among its immediate children, whose message says what to pass instead ([discovery.md](discovery.md#rules-in-order), rule 3), or a repository git cannot read or whose default branch has no commit yet) and `no-commit-before-now` (#70: one per repository whose default branch has no commit before `--now`, which the run leaves out, as it leaves out an excluded one). A `path-failed` warning makes a scan `partial`; `no-commit-before-now` does not, since the repository did not exist yet at `--now`.
- **Determinism.** Two runs on the same inputs and `--now` render byte-identical JSON once `timings` is removed: object fields in a fixed order, map keys sorted, every list sorted. A second scan into the same facts.db also gets the next `run.id` (and `provenance.run_id`), so a comparison across one database removes those too.

Changes from the 2026-10-07 draft:

- `generated_at` is gone: a wall-clock field breaks byte-identical output. The run's start and finish are in `timings`.
- `group_rollups` became `overviews`, one per group, with totals, the people's breadth (repos), depth (majority files), survival and activity, bots, the AI-assisted and bot shares, knowledge loss, concentration, provenance and caveats.
- Every repository has a `card` (age, size, who it is made of, concentration, knowledge loss, AI and bot share, landings, caveats): what an agent or a lead reads first.
- `majority_owner_concentration` moved from `still_here` to `card.concentration` and the overview's `concentration`; `files_with_majority` went with it.
- `policy.weights_applied_to_headline` is gone with open decision #2's weights; `blame_ignore_revs` gained `revs`; `groups[].repo_names` became `groups[].repos`, the repository keys.
- `caveats` (what could make this wrong) are new at every level, and so are `kind`, `run`, `history`, `metrics`, `ranks` and `line_facts`. `timings` lost the cache and hotspot counters until those ship, and `hotspots` returns with M5.
- `provenance.forge.repos[]` gained `from` and `missing` (#101, [ADR 0013](../adr/0013-sync-reads-bounded-passes-and-checks-the-replica.md)), and `updated` now holds only with them: every pull request last updated from `from` until `updated` was in the replica, unless `missing` is not 0. Before, every replica was read from a repository's first pull request, which `from: null` still says, so `updated` read alone overstates a replica a bounded sync wrote. This narrows what `updated` means, which the rule above counts as a change of version; it stays `stillhere.report/v1` because no tag has been cut, so no consumer reads v1 yet (the status line), and a reader written from this page reads the three together.
- 2026-10-15 (#108, #107, #105, PF-5): the `week` rows are `landed@2`'s, who wrote what landed, with `landings` (what `commits` counted before), `commits` (their non-merge commits), `merged`, `lines_added` and `prod_lines_added` (now `null` when unknown) and `landings_lines_unknown`, and each table has the scope's `total`, 0 for a covered window in which nothing landed, while `week` and `totals.landers` are `null` for a window the history does not cover; overviews and cards carry `review_coverage`, with `after_sync` and `unmatched`; overviews start with `repos`, one row per repository; cards carry `areas` and `landings.last`; rank tables carry `beside` and their rows `beside`. No external consumer exists yet, so the version stays `v1`.
- 2026-10-16 (packaged policy revision 3): `policy.revision` and `provenance.policy_revision` name the packaged policy's revision beside its hash; `skipped.history_only`; the `inline-tests` warning; the `Paths` answer of `stillhere paths`.
- 2026-10-16 (wave 10): `review_coverage` counts changes, with `via_other_branch`, `branch_merges`, `copies` and `named_elsewhere`; `week.total` carries `copies`; `still_here` rows carry `merged_365d` beside `landings_365d`, which now counts as `landed@2` credits; a rank row's and a `me` rank's `rank_lo`, `rank_hi`, `lo` and `hi` are `null` where no interval was drawn (below the minimum, or a bot's), not 0; explain's answer gains `coverage[]`, and its `landings[]` `copies`. No external consumer exists yet, so the version stays `v1`.
- Narration, `geared_fp` and `geared_fp_estimated` stay out: narration is specified with the MCP and narrator work in M4, and gearing was cut (open decision #2, decided 2026-10-15). The hotspot row shape lives in [hotspots-code-maat.md](hotspots-code-maat.md).

## Caveats

| Code | When |
| --- | --- |
| `not-fetched` | Always: analysis never fetches, so a stale clone gives a stale report. |
| `failed` | A repository failed and adds nothing. |
| `shallow-clone` | Blame did not run: its surviving lines, ownership and durability are missing. |
| `partial-clone` | No line facts: only its landings and commits count; where its blobs are absent, no path is skipped as too big or generated. |
| `shallow-window` | The shallow boundary is inside the history window: a window that starts after the boundary is still counted, and any other has no value ([metrics.md](../metrics.md#values-what-every-metric-returns), #74). |
| `blame-errors` | Blame failed on some files; their lines are missing. |
| `binary-changes` | A scan's history holds changes to `prod` files, by the path each change wrote, that git took for binary (a NUL byte in a file's first 8,000 bytes, or `-diff` in `.git/info/attributes`): their lines are unknown, so `durable@1` and `simplifying@1` leave them out and the lines landed count none. The caveat counts them (#64). |
| `no-ignore-revs` | A repository with at least 10,000 surviving prod lines has no `.git-blame-ignore-revs`: a formatting commit would take the credit for every line it touched. Wave 11 (KT-10): the repository's caveat names up to three commits that look like a formatting pass, judged from blame alone, so a commit older than the history is judged too: one that holds surviving prod lines in at least a quarter of the repository's prod files that hold lines, and in 10 or more, holds at most a tenth of each such file's lines at the median, holds at least 2% of the repository's surviving prod lines, and is the oldest owner (no line of the file older, by author time) of at most half of those files, most lines first. Each is named by its first 12 hex digits, with whether a bot or a person wrote it (as `identity` tells, where the page has the run's people), its lines, their share and its files. The caveat says how to have blame skip one, by the route that works in any clone: its full SHA in a file, passed to a scan of that repository alone (`git -C PATH rev-parse SHA >> ignore-revs.txt`, then `stillhere scan --ignore-revs-file ignore-revs.txt PATH`; `--ignore-revs-file` is refused on a run of several repositories). It also says that a `.git-blame-ignore-revs` at the repository's root counts only once it is on the commit a scan reads, origin's default branch as last fetched or a mirror's as last synced ([discovery.md](discovery.md#default-branch), [blame-collector.md](blame-collector.md#ignore-revs-per-repository)): a commit made only in the clone is not read. An import, a conversion or a feature holds most of each file it touches, or few files, and a rewrite or an import whose lines were mostly rewritten since created its files, so none is named (`report.formattingCommits` holds the bounds and their evidence). On okhttp, "Reformat with Spotless" and its Spotless 7 pass are named, and its Kotlin conversion of 9,757 lines in 17 files is not; on fzf, "Rewrite fzf in Go", the oldest owner of all 16 files it holds lines in, is not. The bounds are a heuristic, so the caveat asks the reader to check each commit: on 19 repositories they named 14 commits, and 13 were formatting passes or mechanical edits, while the 14th, fzf's refactor that let it be used as a library, was not. The caveat is the repository's in every view: who-knows of a path reads the whole repository's facts for it, so its size, its candidates and their shares are the card's, not the path's. A section over several repositories says so once and points to each repository's own caveat, on its card and in an MCP `overview` of it. |
| `inline-tests` | Prod Rust files at HEAD hold `#[cfg(test)]` items, unit tests inside the source, whose lines count as prod in every number because a file has one role: the caveat counts the files and the lines, and their share of the surviving prod lines ([classification.md](classification.md#rust-inline-tests)). |
| `duplicate-repo` | Another clone of the repository's remote was skipped, so the repository is counted once; on the kept repository's card. |
| `head-after-now` | The run read the newest first-parent commit of the repository's default branch committed before `--now`, because its head is newer: the caveat names the commit read and how many landings came at or after `--now`, which no number counts (the repository's warning, as it stands; a section over several repositories says so once and names them). `provenance.heads` and `repos[].head` record the commit read. |
| `dated-after-now` | Landings below the commit read are dated at or after `--now`, as a backdated commit above newer ones or a clock that ran ahead leaves: blame counts the lines they hold, but no window counts them, so their authors can look inactive. The caveat names the commit read and counts them (the repository's warning, as it stands; a section over several repositories says so once and names them). Only a scan whose blame ran gives it. |
| `excluded-repo`, `path-failed`, `no-commit-before-now` | Run-level warnings, counted, with the first one's reason; `warnings` lists each one. |
| `going-quiet` | Wave 10: people holding lines in the section's scope go quiet within 30 days unless they land, review, open a pull request or commit to a branch (`knowledge_loss`'s `going_quiet`): how many, their lines, and the share once they have. A card and an overview carry it where `knowledge_loss` is. The message names no one, since one sentence serves every format; it says the people are listed with the knowledge loss (`going_quiet.holders`, which text and Markdown print as "going quiet within 30 days:", the first 10 and how many more), and gives the share before and after, with as many decimals as tell them apart. |
| `other-roles` | Wave 10: a who-knows answer counted the lines of roles other than prod in the repositories it names, because the path holds no surviving prod line there (`tests/`, `docs/`): the people listed hold those files, not product code, and the path's knowledge loss and concentration, which count prod lines only, have no value. |
| `uncounted-roles` | Wave 10's review: a who-knows answer counted a path's prod lines where its roles other than prod and test hold more lines (its `uncounted`), as werkzeug's `docs/` holds `docs/conf.py` beside its docs: the people listed know the product code, not the rest, whose own authors it leaves out. Test lines do not count toward it, since tests sit beside the code they test (a Go package's `_test.go` files). Any other answer's totals say what they leave out ("· not counted: 6 test lines in 1 file"). |
| `alias-id` | Wave 10: a person was named by the id of an address git's mailmap now maps to their canonical one, as an id an answer gave before a `.mailmap` change is: it names them, with their id in this run. |
| `unmerged-identities` | Display names that more than one email shares were not merged; a `.mailmap` line merges them if they are one person, and `stillhere identities` (over MCP, `identity_candidates`) suggests the lines with the evidence for each. Names are compared as `identities` compares them (`identity.Directory.NameKey`): case, spacing and punctuation never tell two apart, and a default name (`Your Name`), a bot's and a login's are no name to share, so the caveat names a name exactly when `identities` compares it; one written two ways is printed the first way in byte order. ## Text and Markdown

- **Text** is for a terminal, read top to bottom: the provenance header, what could make the report wrong, the overviews, the ranks, then each repository's card and tables. Every instant it prints is UTC and says so (`as of 2026-10-15 UTC`, a window's `→ 2026-10-15 UTC`, a column head's `(UTC)`, #79). An overview starts with its repositories' table (#105); a card ends with its areas. A page is concise by default (SR-14): each table of people, each rank table's ranked rows, a card's areas (5) and an explanation's changes, landings, commits and files print their first 10 rows and count the rest, the people below a rank table's minimum are one line that counts them, and an overview that covers one repository, whose card follows on the page, is left out, so no person is listed twice; `--all` (report, scan, week, explain) prints every row. JSON always holds every row and every overview. `explain` prints each value's detail below its table, wrapped, never cut (PF-5). No line is wider than 100 columns, except one that holds a single unbreakable word such as a URL: headers wrap like prose, and a table too wide for the line cuts its widest text columns (names, titles, details) with `…`, none below 8 columns; numbers are never cut. Untrusted text (names, paths, subjects, git messages) is printed with control and format characters escaped as Go quotes them, so an escape sequence in an author name cannot reach the terminal.
- **Markdown** is GitHub-flavoured, with the same sections, for pasting into an issue or a pull request. Untrusted text is backslash-escaped and `&` becomes `&amp;`, so `<img src=x>` and `Frank & Sons` render as text; paths, SHAs and remotes are code spans. GitHub would link `@name` as a mention, which notifies that account, and `#12` as a reference, which posts a back-link on issue 12, so `@` and `#` in untrusted text are followed by a word joiner (U+2060): the text reads the same and links nobody. A repository's local path is left out, though a warning that concerns a path still names it.
- **Neither** prints an email. Ranked metrics appear only as rank tables, with their 95% intervals, the people below the minimum listed and not ranked, and bots apart ([ADR 0001](../adr/0001-measure-changes-rank-per-metric.md)): a table sorted by a ranked metric's point values would be a rank without its uncertainty.

## Exit codes

| Code | When |
| --- | --- |
| 0 | At least one repo produced week or still-here facts. This includes partial failure, clone-health skips, and skipped hotspots. For `sync github`, at least one repository synced, a partial sync included: its last line on stdout, printed after every sync that began its run, says how many repositories synced, failed, or are missing pull requests, and how many pull requests it read, so a scheduled sync's log tells them apart (`sync github: 5 of 6 repositories synced, 1 failed; 1464 pull requests read in 1m58s`). |
| 1 | No repo produced facts: every path failed, none was a repo, or `--exclude-repo` left none. The report is still printed, with each repository's error, and a scan stores no run. A read command asked about a run or a person the database does not hold also exits 1, and its error line names the database and says what to do (#71); so does `label` when the run holds no change to label, after the caveats that say why (`nothing-to-label`). |
| 2 | A usage error (see below). |
| 128 + n | Interrupted by signal n (SIGINT, SIGTERM or SIGHUP). stillhere stops every git process, prints `stillhere <command>: interrupted` (#71), then ends itself with the same signal, so a shell sees it die by that signal (`$?` is 130 for Ctrl-C) and stops a loop. Where a process cannot signal itself (Windows), it exits 130. A scan interrupted after it began writing marks its run failed, which no reader sees. |

Usage errors:

- missing paths, said as `scan needs at least one PATH: …` (RB-19), or an unreadable policy file;
- a policy file over 1 MiB, an empty one, or an implicit `./stillhere.toml` or `./.mailmap` that is a symbolic link, which a clone can supply (#71; a file `--policy` or `--mailmap` names may be one);
- a facts.db a read command (`report`, `explain`, `who-knows`, `me`, `identities`, `validate`, `label`) is pointed at that does not exist, which it never creates, or one, or its directory, that `scan` or `sync` cannot write, before any git work (#71); the message names the path. A read command, and the MCP server, read a facts.db in a directory they cannot write read-only, as SQLite allows when its write-ahead log holds nothing (`immutable=1`); one whose log holds commits there is a usage error that says to make the directory writable or copy both files, and so is a read while another user's scan or sync writes the database, which SQLite's lockless read could not keep out (#79);
- a relative `STILLHERE_HOME`, which would name another facts database in every directory a command runs in (RB-12);
- a `sync github --org` that is no GitHub login, or a `--repo` that is not `OWNER/NAME` with GitHub names, refused before the sync begins its run; `--org` and `--repo` together, or neither; a `--since` that is not in the past; a `--repo` GitHub has no repository for, or does not show the token, and an `--org` it does not know, which begin no run either and print no closing line; and a `--db`, `--mirrors` or `STILLHERE_HOME` that is a URL or holds a credential where a local path belongs (#71, #111);
- a user policy that lacks a required table: `headline`, `week`, `blame`, `bots`, `ai`, `roles`, `paths`, plus `hotspots` once M5 ships (`gearing` was cut: open decision #2, decided 2026-10-15);
- `--ignore-revs-file` on a multi-repo run, or one that cannot be read;
- a malformed `--exclude-repo` glob, `--rank` on a metric that is never ranked, or a metric id the registry does not know;
- git older than the supported floor ([git-invocation.md](git-invocation.md#version-floors));
- for `validate` and `label`: the default labels file missing (`validate`: no labels yet, and what writes them), a labels file over 16 MiB, one that is not a regular file (a FIFO, a device, a directory), a malformed one (the line named), one with no label (`validate`, with how many rows were skipped or read as comments), `--labeller` naming no row's labeller (`validate`), `--sheet` with `--plan`, `--format` other than text for the interactive session, and `--n` outside 1 to 10,000.
